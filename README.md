# cim-anonymizer

Потоковое **детерминированное обезличивание CIM RDF XML** (МЭК 61970-301 / 61968-11)
для моделей класса «КТС Мониторинг». Инструмент заменяет персональные данные,
наименования объектов и идентификаторы синтетическими значениями, при этом:

* граф связей между объектами остаётся целым (с точностью до переименования вершин);
* одинаковые значения всегда дают одинаковый результат, различные — различный;
* файлы размером в сотни мегабайт и десятки гигабайт обрабатываются без загрузки в память;
* без секретного ключа исходные значения восстановить нельзя.

## Содержимое каталога

| Путь | Назначение |
|---|---|
| `cim_anonymizer_v2.py` | Основной модуль: CLI, два прохода по файлу, все правила замены (~970 строк). |
| `verify_v2.py` | Скрипт проверки результата: ссылочная целостность, утечки идентификаторов и значений, совпадение набора классов, вложения, пролог. |
| `cim_anonymizer/__init__.py` | Пустой пакет (заготовка под `uv`-скрипт `cim-anonymizer`, см. «Известные ограничения»). |
| `__init__.py` | Пустой файл. |

Вспомогательные скрипты для создания небольших образцов исходного файла лежат
отдельно в [`../mini/`](../mini/README.md).

## Требования

* Python **≥ 3.14** (см. `.python-version` и `pyproject.toml`);
* [`lxml`](https://lxml.de/) ≥ 6.1.3 — единственная внешняя зависимость;
* рекомендуется [`uv`](https://docs.astral.sh/uv/) для окружения (`uv.lock` в репозитории).

```bash
uv sync
```

Без `uv`:

```bash
python -m venv .venv && source .venv/bin/activate
pip install lxml
```

## Быстрый старт

```bash
uv run python src/cim_anonymizer_v2.py \
  --input  data/input.xml \
  --output output/output.xml
```

Каталоги `data/` и `output/` в `.gitignore`: исходные и обезличенные модели не
попадают в репозиторий (сохраняются только пустые маркеры `.gitsave`).

### Аргументы командной строки

| Аргумент | Обязательный | Описание |
|---|:---:|---|
| `--input` | да | Исходный CIM RDF XML. |
| `--output` | да | Путь результата. Недостающие каталоги создаются. |
| `--secret-file` | нет | Файл ключа. По умолчанию `<output>.anon_secret` рядом с результатом. |
| `--keep-coords` | нет | Не сдвигать координаты (`xPosition` / `yPosition`). По умолчанию координаты сдвигаются. |

### Секретный ключ

Все замены считаются как `BLAKE2b(key=SECRET)`, поэтому результат определяется
парой «входной файл + ключ». Ключ берётся в таком порядке:

1. переменная окружения `ANON_SECRET`;
2. файл ключа (`--secret-file` или `<output>.anon_secret`), если он существует и не пуст;
3. иначе генерируется 48 случайных байт и сохраняются в файл с правами `0600`.

Что из этого следует:

* **один и тот же ключ → один и тот же результат** при повторных запусках, а также
  совпадающие UUID и числовые идентификаторы в разных файлах, обезличенных одним ключом
  (имена при этом могут расходиться, если в файлах по-разному разрешаются коллизии);
* **потерянный ключ** означает, что воспроизвести результат нельзя;
* **утёкший ключ** позволяет подбором проверять гипотезы «это значение — вот этот
  оригинал» (для идентификаторов и имён с малым пространством значений). Храните
  ключ отдельно от обезличенных данных и не публикуйте его.

## Как это работает

Обработка идёт в два потоковых прохода через `lxml.etree.iterparse` с очисткой
уже обработанных элементов (`_cleanup`), поэтому потребление памяти почти не
зависит от размера файла. Разбор выполняется с `huge_tree=True`.

### Проход 1 — `pass1`: сбор справочников

Читает все верхнеуровневые объекты (дети `rdf:RDF`) и собирает значения, которые
нужно заменить, чтобы построить **биекции** «оригинал → синтетическое значение»:

* наименования объектов (`name`, `aliasName`, `nameplate`, `folderName`, `className`, `dispatchName`, `locName`) с запоминанием класса объекта;
* ФИО абонентов (`Customer.name`);
* ФИО и части ФИО сотрудников (`Person.lastName / firstName / middleName / name`);
* улицы, города, регионы и страны из `StreetDetail.*` и `TownDetail.*`;
* словарь значений и слов из вложений (атрибуты внутри `MonitelDiagram.image` и `ACLineSegment.sections`).

Объекты класса `FullModel` пропускаются — метаданные модели не трогаются.

После сбора справочников строится индекс для маскирования свободного текста
(`build_text_index`). Частые значения — встречающиеся более 50 раз
(`rare_limit`), например технические подписи вроде `Imax` или `switch device`, —
в индекс не попадают, чтобы не портить обычный текст. Исключение — значения из вложений.

### Проход 2 — `pass2`: замена и потоковая запись

Повторно читает файл, заменяет значения по правилам и сразу пишет результат
на диск. Перед корневым элементом дословно копируются XML-декларация, PI-инструкции
(`<?iec61970-552?>`, `<?floatExporter?>`) и комментарии; открывающий тег корня
сохраняется как есть. Чтобы вывод не раздувался, объявления `xmlns:*` корня
вырезаются из сериализованных дочерних объектов.

### Правила замены

| Данные | Поля | Результат |
|---|---|---|
| **Идентификаторы-ссылки** | `rdf:about`, `rdf:resource` (значения вида `#_uuid`) | Новый UUID = `BLAKE2b(key, "id\|uuid")`. Один и тот же исходный UUID → один и тот же новый, ссылки остаются валидными. Формат `#_<uuid>` сохраняется. |
| **Прочие UUID в полях** | `fiasId`, `fiasStreetId` и другие поля из `ID_LAST`, если значение — UUID | Отдельное отображение `map_uuid_value`. |
| **Числовые идентификаторы** | `mRID`, `mRIDStr`, `serialNumber`, `ccsCode`, `tabNumber`, `personalNumber`, `passportNumber`, `accountNumber`, `phoneNumber`, `inn`, `kpp`, `okpo`, `buildingName`, `Asset.type` | Каждая последовательность цифр заменяется числом **той же длины**; общий кэш даёт связность (число → одно и то же число везде). Тождественная замена исключается. Нецифровые символы сохраняются. |
| **Наименования объектов** | `name`, `aliasName`, `nameplate`, `folderName`, `className`, `dispatchName`, `locName` | `«<прилагательное из овощей/фруктов> <Класс>-<HEX-суффикс>»`. Класс объекта сохраняется (ТП остаётся ТП, ПС — ПС), суффикс получается из хэша. |
| **Абоненты** | `Customer.name` | Синтетическое ФИО «Фамилия Имя Отчество» из справочников. |
| **Сотрудники** | `Person.lastName / firstName / middleName / name` | Синтетическое ФИО; части согласованы между собой. |
| **Адреса** | `StreetDetail.name`, `TownDetail.name / stateOrProvince / country` | Синтетические улицы, города, регионы (район/край/область/округ) и страны. |
| **Свободный текст** | `description`, `text`, `textTemplate`, `comment`, `notes` | См. ниже. |
| **Вложения** | `MonitelDiagram.image`, `ACLineSegment.sections` | Base64 декодируется, содержимое (ZIP с XML или чистый XML) маскируется изнутри, кодируется обратно. PNG и прочие бинарные данные не меняются. |
| **Координаты** | `xPosition`, `yPosition` | Детерминированный сдвиг до ±0,05 на объект; число знаков после запятой сохраняется. Отключается `--keep-coords`. |

#### Уникальность значений

Класс `Uniquer` гарантирует биекцию: если синтетическое значение уже занято,
подбирается вариант (другая фамилия, более длинный хэш-суффикс, затем номер).
Так «различные значения → различные новые, одинаковые → одинаковые», и
статистика по значениям сохраняется. Число разрешённых коллизий выводится в логе.

#### Маскирование свободного текста

`mask_text` выполняет три шага:

1. **Точные упоминания.** Все ранее найденные реальные наименования, ФИО, улицы, города, регионы и страны заменяются на их синтетические двойники.
2. **Слова.** Кириллические слова длиной от 4 символов из справочников заменяются на синтетические слова (`synth_word`).
3. **ПДн-паттерны:**
   * email → `user.<hash>@example.test`;
   * российский телефон (`+7` / `8`) — цифры заменяются по общему кэшу;
   * серия и номер паспорта `NNNN NNNNNN`;
   * СНИЛС `NNN-NNN-NNN NN`;
   * ФИО с инициалами (`Иванов И.И.`, `И.И. Иванов`) → синтетическая фамилия с инициалами.

Результат кэшируется по исходной строке, так как тексты в моделях часто повторяются.

#### Вложения

Внутри вложений маскируются:

* атрибуты из `DIAG_MASK_ATTRS` (`Description`, `Name`, `ElementName`, `Text`, `ItemName`, `Label`, `Caption`, `Nameplate`, `Comment`, `TextValue`, `Title` и их варианты в нижнем регистре);
* в `Nameplate` дополнительно маскируются цифры (заводские марки);
* значения-UUID в атрибутах — **тем же отображением, что и `rdf:about`**, поэтому ссылки диаграмм на объекты модели остаются валидными;
* текстовое содержимое элементов.

ZIP пересобирается с фиксированной датой (`1980-01-01`), чтобы результат
был воспроизводимым побайтово. Файлы внутри архива с расширениями
`.xml`, `.txt`, `.rels`, `.scrap` обрабатываются, остальные копируются без изменений.
Если вложение не удалось разобрать, оно остаётся без изменений.

### Справочники синтетических значений

Все справочники находятся в начале `cim_anonymizer_v2.py` и состоят из названий
овощей, фруктов и злаков: `FRUIT_VEG_ADJ`, `_SURNAMES`, `MALE_NAMES`,
`PATRONYMICS`, `TOWNS` (собираются из основ и окончаний), `COUNTRIES`,
`STREET_TYPES`. Сгенерированные ФИО мужские. Реальные люди и места в них не
используются, email формируется в домене `example.test` (зарезервирован RFC 2606).

### Настройка правил под свою модель

Классификация полей задаётся наборами констант в начале модуля. Чтобы
обезличивать дополнительные поля, достаточно расширить нужный набор:

| Константа | Что определяет |
|---|---|
| `NAME_LAST` | Наименования (последний сегмент имени тега, в нижнем регистре). |
| `ID_LAST`, `ID_FULL` | Числовые / UUID-идентификаторы (последний сегмент или полное локальное имя). |
| `FREE_LAST` | Поля свободного текста. |
| `ATTACH_FIELDS` | Поля с вложениями (полное локальное имя, в нижнем регистре). |
| `PERSON_CLASSES`, `CUSTOMER_CLASSES` | Классы сотрудников и абонентов. |
| `STREET_CLASSES`, `TOWN_CLASSES` | Классы адресных данных. |
| `SKIP_TEXT_CLASSES` | Классы, которые не трогаются (по умолчанию `FullModel`). |
| `DIAG_MASK_ATTRS`, `DIAG_DIGIT_ATTRS` | Атрибуты внутри вложений, которые маскируются целиком или вместе с цифрами. |

Имена тегов сравниваются в нижнем регистре, по **последнему сегменту** локального
имени после точки (`Asset.type` → `type`), если константа не помечена как «полное имя».

## Проверка результата — `verify_v2.py`

Скрипт сравнивает исходный и обезличенный файлы, также потоково. Он проверяет:

1. **ссылочную целостность** — количество `rdf:about` и `rdf:resource`, число «висячих» ссылок в исходнике и в результате;
2. **утечки идентификаторов** — пересечение множества `rdf:about` до и после (должно быть 0);
3. **набор классов** — совпадение счётчиков классов в исходном и обезличенном файлах;
4. **число различных `*.name`** в результате;
5. **утечки значений** в XML-тексте по списку `LEAK_PROBES` (поля длиннее 120 символов пропускаются);
6. **утечки внутри вложений** — выборка из 300 вложений: распаковка base64/ZIP и поиск тех же проб;
7. **пролог результата** — XML-декларация и PI-инструкции.

Запуск (пути жёстко заданы в начале файла):

```bash
uv run python src/verify_v2.py
```

Скрипт читает `./data/input.xml` и `./output/output.xml`, поэтому запускайте его
из корня репозитория. Перед использованием:

* замените `LEAK_PROBES` на значения **из вашей модели**, которые не должны остаться
  в результате. Текущий список содержит значения из конкретного набора данных и не подходит для других моделей;
* число «120062» в строке про `name`-значения — константа от конкретного исходного файла, обновите её;
* проверка выполняется при импорте файла (функций-обёрток и `main()` нет).

## Типичный рабочий цикл

```bash
# 1. положить исходную модель
cp /path/to/model.xml data/input.xml

# 2. обезличить (ключ можно задать заранее)
export ANON_SECRET='длинная-случайная-строка'
uv run python src/cim_anonymizer_v2.py --input data/input.xml --output output/output.xml

# 3. проверить
uv run python src/verify_v2.py
```

Для разработки на больших файлах удобнее брать компактные образцы,
собранные скриптами из `mini/` — подробности в [`../mini/README.md`](../mini/README.md).
Образцы **не обезличены**, не публикуйте их.

## Известные ограничения

* **Консольная команда не подключена.** В `pyproject.toml` объявлен скрипт
  `cim-anonymizer = "cim_anonymizer:main"`, но `src/cim_anonymizer/__init__.py`
  пуст, поэтому `uv run cim-anonymizer` пока не сработает. Запускайте
  `src/cim_anonymizer_v2.py` напрямую.
* **Только `rdf:about` / `rdf:resource`.** Атрибут `rdf:ID` не обрабатывается.
  Ссылки `rdf:resource`, не начинающиеся с `#`, не меняются.
* **Только русскоязычные данные.** Регулярные выражения ПДн (телефон `+7`/`8`,
  ФИО с инициалами, паспорт, СНИЛС) и слова из справочников рассчитаны на кириллицу.
  Латинские имена из свободного текста обезличиваются только как точные
  совпадения с ранее найденными наименованиями.
* **Сгенерированные ФИО только мужские** — отчества и имена берутся из мужских списков.
* **Редкие значения полагаются на справочник.** Упоминание реального имени в
  свободном тексте маскируется, только если оно встретилось в полях наименований,
  ФИО, адресов или вложений. Незнакомые имена ловятся лишь общими
  паттернами. После обезличивания всегда запускайте проверку и просматривайте результат.
* **Глобальное состояние.** Ключ хранится в глобальной переменной `KEY` модуля,
  поэтому в одном процессе нельзя параллельно обезличивать данные с разными ключами.
* **Параметры не конфигурируются из CLI:** порог частоты (`rare_limit=50`), размер
  заголовка для чтения пролога (8 МБ), амплитуда сдвига координат (±0,05) заданы в коде.
* **Не заменяются** метаданные `FullModel`, PNG-вложения (`Icon`) и поля, не
  перечисленные в константах классификации.
